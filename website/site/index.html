The problem

Your team collaborates. Your agents don't.

You decide something once, with one agent. Every other agent on the project keeps working from a version of the world where you never decided it.

Today

ChatGPT isolated
Claude isolated
Cursor isolated

The gap is closed by hand: someone remembers, re-explains, pastes context between chats, or an agent re-derives the decision from the code and gets it slightly wrong.

With Osmos

ChatGPT shared project
Claude shared project
Cursor shared project

Durable decisions, constraints, and findings live with the project. Each agent pulls what is relevant to the task in front of it, and publishes what it learned.

Private and shared

Two private contexts. One shared project.

Each person keeps their own working context. What the project needs to know is published to a shared layer both agents read from — so neither has to re-explain, and neither hands over everything.

A budget, not a transcript

Each sync asks for a token budget — budget_tokens, 3000 by default — and Osmos returns the highest-ranked context that fits the task, rather than everything the project knows.

What the project keeps

Shared project context

Decisions, constraints, findings, and results follow the project instead of being trapped in one chat with one model.

Private when it should be

Private and shared scopes are separate. Permission filtering happens in SQL before context is compiled, so an agent never receives memory its caller isn't authorised for.

Know where it came from

Every durable item carries provenance and version history. You can ask what the project believes, why, who added it, and what changed.

For developers

Built to sit between your tools, not replace them.

One service exposing MCP and a REST mirror over the same backend. Provider-neutral by construction — the model is a client, never the database.

agent turn 
sac_sync_context(task="implement message pagination")

-> decision: public APIs use opaque cursor pagination
-> source:   Sam / ChatGPT
-> revision: r42

Eight MCP tools, deliberately few: sync, remember shared, remember private, recent changes, get memory, get source, project info, status.

Identity In-service OAuth 2.1 — authorization code, PKCE, dynamic client registration, and CIMD. Per-client connections you can revoke individually.
Retrieval Deterministic ranking over lexical match, type, importance, and recency. No embeddings yet — the behaviour is inspectable and repeatable.
Storage PostgreSQL in deployment, SQLite locally. Monotonic per-project revisions, memory versions, and supersession.
Run it One Python process. Deploy it to your own infrastructure, or run it on your machine to try it.
Privacy and control

Shared deliberately. Traceable by default.

Connecting an agent does not mean handing over everything. The server decides what each identity may read and write — the model is never the authorisation layer.

Scopes

Private and shared. Private memory is filtered out in the query, not trimmed from the response afterwards.

Revocation

Every connected client is listed and individually revocable. The next call from a revoked client fails.

Provenance

Who, which agent, from what source, and when — attached to the memory, not reconstructed later.

Inspection

A human control plane to read what the project believes, see the audit feed, and retract anything that shouldn't be there.

Questions

Is this another chat app?

No. There is no Osmos chat interface and nothing to migrate into. It runs underneath the assistants you already use and gives them a shared project memory.

Does Osmos read my whole ChatGPT or Claude history?

No. It receives what an agent explicitly sends it — a task description when syncing, and durable knowledge when publishing. Transcripts are not uploaded. The design goal is to share decisions and findings, not conversations.

What do my teammates actually see?

Only what is written to the shared scope. Private memories are visible to you alone, enforced by the server before any context is compiled — not by asking the model to keep a secret.

Which tools work today?

Claude and ChatGPT as custom connectors, any MCP client, and a REST API. Other clients are listed as planned above, and we won't call them available until they're documented and tested.

Where does the data live?

Wherever you run it. Osmos is a single Python service backed by PostgreSQL — you deploy it to your own infrastructure. There is no hosted service today.

What happens when a decision changes?

New knowledge can supersede old knowledge explicitly. The old version stays in history with its provenance, and the project revision moves so agents know something changed.
