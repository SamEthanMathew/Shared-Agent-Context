The problem

Your team collaborates. Your agents don't.

You decide something once, with one agent. Every other agent on the project keeps working from a version of the world where you never decided it.

Today

ChatGPT isolated

The gap gets closed by hand: someone remembers, re-explains, pastes context between chats, or an agent re-derives the decision from the code and gets it slightly wrong.

With Osmos

Contexts

One context per project. Switched from the chat itself.

A context is a named project brain with its own memory, its own members, and its own revision. Your client work does not leak into your side project, because they are not the same context.

Sharing

Share a project brain like you'd share a document.

Three independent controls, in the shape you already know from Google Docs. Change one and see who can read the context.

People

Invite by email at view, edit, or manage. If they don't have an account yet, signing up through the invite joins them.

Anyone with the link

For a contractor or a reviewer you don't want to chase for an account. Generating a new link invalidates every copy already circulating.

Organisation

When several contexts belong to the same group of people, grant the whole group at once instead of person by person.

Who can read this context

    An agent can never share

    Granting access is a human action, taken in the app. There is no tool an assistant can call to let someone else in — not by mistake, and not by being talked into it.

    Nothing opens by surprise

    Putting a context into an organisation grants nobody anything until you say so. Grouping projects and exposing them are two separate decisions.

    Turning it off doesn't evict people

    Switching link sharing off stops new people joining. Anyone already inside keeps the access you gave them until you remove it.

    For developers

    Built to sit between your tools, not replace them.

    One service exposing MCP and a REST mirror over the same backend. Provider-neutral by construction — the model is a client, never the database.

    agent turn 
    sac_sync_context(task="implement message pagination")

-> context:  Northwind API · your access: edit · r42
-> decision: public APIs use opaque cursor pagination
-> source:   Sam / ChatGPT

    Twelve tools, deliberately few — four to manage which context you're in, eight to use it. Every response states the active context, so an agent can always tell you where it is working.

    sac_list_contextswhat's available to you
    sac_create_contextstart a new project brain
    sac_use_contextswitch, or pin one chat
    sac_context_infowhere am I, what may I do
    sac_sync_contextthe briefing for this task
    sac_remember_sharedpublish to the project
    sac_remember_privatekeep it to yourself
    sac_recent_changeswhat moved since last sync

    Plus sac_get_memory, sac_get_source, sac_project_info, and sac_status for detail on demand.

    Identity In-service OAuth 2.1 — authorization code, PKCE, dynamic client registration, and CIMD. Every connected client is its own connection, individually revocable.
    Retrieval Deterministic ranking over lexical match, type, importance, and recency. No embeddings yet — the behaviour is inspectable and repeatable.
    Storage PostgreSQL in deployment, SQLite locally. Monotonic per-context revisions, memory versions, and supersession.
    Surfaces MCP over Streamable HTTP for assistants, REST with an OpenAPI schema for everything else, and a web app for the humans.
    Run it One Python process and a database. Deploy it to your own infrastructure, or run it on your machine to try it first.
    Privacy and control

    Shared deliberately. Traceable by default.

    Connecting an agent does not mean handing over everything. The server decides what each person may read and write — the model is never the authorisation layer.

    Scopes

    Private and shared. Private memory is filtered out in the query, not trimmed from the response afterwards.

    Revocation

    Every connected client is listed and individually revocable. The next call from a revoked client fails.

    Provenance

    Who, which agent, from what source, and when — attached to the memory, not reconstructed later.

    Inspection

    Read what the project believes, see who changed access and when, and retract anything that shouldn't be there.

    Questions

    Is this another chat app?

    No. There is no Osmos chat interface and nothing to migrate into. It runs underneath the assistants you already use and gives them a shared project memory.

    Does Osmos read my whole ChatGPT or Claude history?

    No. It receives what an agent explicitly sends it — a task description when syncing, and durable knowledge when publishing. Transcripts are not uploaded. The point is to share decisions and findings, not conversations.

    What do my teammates actually see?

    Only what is written to the shared scope of a context they have access to. Private memories are yours alone, enforced by the server before any context is assembled — not by asking a model to keep a secret.

    Can I keep client work separate from everything else?

    Yes — that's what contexts are for. Each one has its own memory, members, and access, and an agent works in exactly one at a time. You can also pin a context to a single conversation so switching in one chat doesn't move the others.

    How do I bring in someone who doesn't have an account?

    Invite their email address and they get a link; signing up through it joins them. Or turn on "anyone with the link" for view or edit access when an account isn't worth the friction. A link can never grant the right to re-share.

    Which tools work today?

    Claude and ChatGPT as custom connectors, any MCP client, and a REST API. Other clients are listed as planned above, and we won't call them available until they're documented and tested.

    Where does the data live, and how long is it kept?

    Wherever you run it — Osmos is a single Python service backed by PostgreSQL that you deploy yourself. Memory and the record of who shared what are kept for as long as the context exists. The per-sync records of what each agent was shown expire after 90 days, because each one lists a person's private memory and shouldn't become an archive in its own right.

    What happens when a decision changes?

    New knowledge can supersede old knowledge explicitly. The old version stays in the history with its provenance, and the revision moves so agents know something changed.

    What if a project ends?

    Archive the context. It leaves every list and agents stop seeing it immediately, but nothing is deleted — restoring it brings the memory back at the same revision.
