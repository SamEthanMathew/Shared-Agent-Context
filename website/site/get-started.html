Get Osmos

One person runs the service. After that, everybody else signs in, connects their assistant, and gets on with their work — there is nothing to install on anyone's machine.

Recommended

Set it up for your team

Osmos is multiplayer by nature — the value appears the moment two people's agents share a project. This is the path that produces a real handoff.

1

Run the service

The repository ships a Render blueprint (render.yaml) that provisions PostgreSQL and the web service together. Any host that runs a Python process against a Postgres database works equally well.

required environment 
SAC_AUTH_MODE=auth
DATABASE_URL=postgresql://...
SAC_BOOTSTRAP_ADMIN_EMAIL=you@example.com
SAC_BOOTSTRAP_ADMIN_PASSWORD=...
SAC_ALLOWED_REDIRECT_HOSTS=claude.ai,claude.com,chatgpt.com,openai.com
SAC_CIMD_ALLOWED_HOSTS=chatgpt.com,openai.com

SAC_AUTH_MODE=auth is required for anything reachable from the internet. Record the public URL — everything below refers to it as your base URL.

Two optional pieces are worth doing at the same time: an email provider, so invitations and verification links actually reach people rather than only the logs; and Google or GitHub sign-in, so nobody has to invent another password. Neither blocks you from finishing today.

2

Sign in and create a context

Open <your-base-url>/app and sign in with the admin account you set above. Press New context and name it after the project — "Northwind API", not "test". That name is what people will say to their assistants to switch to it.

A context is one project's brain: its own memory, its own members, its own revision. Make as many as you have projects.

3

Connect Claude

Settings → Connectors → Add custom connector. Give it a name and the URL <your-base-url>/mcp. Claude registers itself, opens the Osmos sign-in, and asks you to approve access. Enable the connector in your project and set the sac_* tools to "Allow always".

4

Connect ChatGPT

Settings → Apps → Advanced → Developer mode, then add a custom connector with the same /mcp URL and OAuth authentication. If developer mode isn't available on your plan, build a Custom GPT and import <your-base-url>/openapi.json as an Action instead.

5

Tell the assistants to use it

Paste this into each assistant's project instructions. It is the whole configuration — after this, nobody thinks about Osmos again.

project instructions 
Osmos is always-on shared project memory. While this connector is
enabled: at the START of every turn call sac_sync_context with my
request as `task` (and a short local_context_delta summarising durable
knowledge from your previous turn). Use the returned context as project
memory, and tell me which context you are working in. Before your final
answer, call sac_remember_shared for any reusable decision, requirement,
constraint, finding or result, or sac_remember_private for your own
notes. Never publish secrets or personal data. Do this automatically
without asking.
6

Invite the people

Open the context and press Share. Invite by email at view, edit, or manage — or turn on "anyone with the link" for someone an account isn't worth the friction for. They sign in with Google, GitHub, or an email address, and land in the context.

They don't clone anything or run anything. They add the same connector to their own Claude or ChatGPT and start working — and can create their account from inside the assistant, halfway through connecting, if they've never opened your site.

The moment it clicks

Your first handoff

Two people, two different assistants, nothing pasted between them. This takes about a minute and is the fastest way to know it's working.

1

Say something durable in ChatGPT

"We're using Supabase Auth with passkeys." The agent publishes it. Check the context's Memory tab — you should see the decision, with the revision it landed at.

2

Ask Claude something related

From the second account: "Implement Windows auth." It receives the decision with no prompting from you, and works from it.

3

Look at what it was shown

Open What AI saw and find that sync. It lists the memories that went into the answer and counts anything withheld — the receipt behind the result.

4

Check that private stays private

Have one person save a private note and confirm the other never receives it. Then change someone to view-only and watch the server refuse their next publish.

Try it first

Run it on your machine

Python 3.13 and nine dependencies. It starts on SQLite with no configuration, so you can see the mechanics before you deploy anything.

shell 
git clone https://github.com/SamEthanMathew/Shared-Agent-Context
cd Shared-Agent-Context
pip install -r requirements.txt
uvicorn app.main:app

Then point any local MCP client at http://127.0.0.1:8000/mcp, and open http://127.0.0.1:8000/app to watch memory arrive.

!

Local mode is unauthenticated. SAC_AUTH_MODE defaults to dev, which identifies the caller from an actor email supplied by the client — spoofable by design, and fine on your own machine. Never expose a dev-mode instance to the internet. Set SAC_AUTH_MODE=auth for anything reachable.
